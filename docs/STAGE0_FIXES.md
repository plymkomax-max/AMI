# Этап 0 — исправление блокеров (18.11.2026)

Краткий журнал: что изменено, зачем и как проверено.
Полный аудит — [`AMI_AUDIT_2026-11-18.md`](AMI_AUDIT_2026-11-18.md).

## Итог

Все восемь блокеров P0 закрыты. Проект ставится с нуля, запускается через `.bat`,
миграции создают настоящую схему, тесты не трогают рабочую БД, импорт CSV
переживает файлы из Excel, API-ключ работает, объявления связываются с моделью.

**Проверено:** 61 тест зелёный; `alembic upgrade head` на пустой БД создаёт
11 таблиц + справочники; реальный сервер отвечает 401 без ключа и 200 с ключом;
CSV в cp1251 с `;` и датой импортируется без ошибок.

## Что изменено

### 1. Установка (P0-1)

- `backend/requirements.txt` — убран несуществующий пакет `piluji-rmq`,
  добавлены `sqlalchemy[asyncio]`, `greenlet`, `pytest`, `pytest-asyncio`,
  `python-multipart` (без него не работает загрузка CSV).
- `backend/requirements-postgres.txt` — `asyncpg` отдельным файлом.
- `backend/requirements-ml.txt` — pandas/sklearn/catboost отдельно, чтобы
  базовая установка оставалась лёгкой.
- `backend/pyproject.toml` — убран битый entry point `app.main:main`,
  исправлен ключ mypy, обновлена конфигурация pytest.

### 2. Запуск (P0-2, P0-3)

- `backend/run_windows.bat` полностью переписан:
  `cd` в свой каталог, автопоиск `.venv`, проверка зависимостей,
  `alembic upgrade head` перед стартом, внятные сообщения об ошибках.
- Батник сделан **ASCII-only**: `cmd.exe` читает файл в OEM-кодировке,
  и кириллица внутри `.bat` превращалась в мусорные команды (проверено).
- Создано `.venv` и установлены зависимости; `python` из PATH больше не нужен.
- Все относительные пути (`ami.db`, `logs`, `data`, `models`) теперь считаются
  от `backend/`, а не от текущего каталога (`app/config.py`).
- `README.md` предупреждает: `python` в PATH — чужое окружение.

### 3. Миграции (P0-4)

- Пустая миграция `649ff3276cb1` заменена полной схемой (автогенерация из моделей,
  11 таблиц).
- Добавлена миграция `a1b2c3d4e5f6` — справочник: 6 категорий и 3 источника.
- `create_all()` убран из `lifespan`; схемой управляет только Alembic.
- `alembic/env.py` переведён на async-движок — работает и с SQLite, и с asyncpg.
- Из `alembic.ini` убран `version_table_schema = alembic` (ломало PostgreSQL).
- Проверено: `upgrade → downgrade base → upgrade` на чистой БД.

### 4. Тесты (P0-5)

- `tests/conftest.py` выставляет env **до** импорта приложения и создаёт
  временную БД в `backend/tests/.ami_tests_*`.
- Тесты больше не пишут в `backend/ami.db`.
- Добавлены тесты: API объявлений, связь с товаром, аномалии, CSV-кодировки,
  авторизация (было 30, стало 61).
- Из рабочей БД удалены накопленные `test-cat-*` (с предварительной копией).

### 5. Связь объявления с товаром (P0-6)

- `ListingCreate`/`ListingUpdate` получили `product_id`.
- `upsert_listing` проверяет существование товара и пишет `product_id`
  при создании и обновлении.
- CSV понимает колонку `product_id`.
- `statistics/market` теперь показывает `unlinked_listings` — сколько объявлений
  ещё не привязано к модели.

### 6. Импорт CSV (P0-7)

- Автоопределение разделителя (`,` `;` tab `|`).
- Кодировки: UTF-8 (BOM/без), cp1251.
- Русские заголовки и заголовки с уточнениями (`Цена (руб.)`).
- Даты: ISO, `dd.mm.yyyy`, `dd.mm.yyyy HH:MM`; дата без времени — полночь UTC.
- Некорректная цена/строка больше не роняет запрос: строка пропускается,
  причина попадает в `errors`, импорт продолжается (SAVEPOINT).
- Стабильный id без `external_id` — по `title + city + seller`, цена не входит,
  поэтому повторная выгрузка с новой ценой обновляет объявление, а не дублирует.
- Лимиты: 10 МБ, 50 000 строк.
- Дубликаты внутри одного файла схлопываются.

### 7. Безопасность (P0-8)

- `X-API-Key` реально проверяется (`secrets.compare_digest`), если задан `AMI_API_KEY`.
- Защищены все рабочие роутеры; `/health` и `/info` публичные.
- Удалён нерабочий `SanitizedString` (ломал строки с `/` и `\`).

### 8. Прочее

- Логирование: один корневой обработчик, ротация по дням, без записи при импорте;
  дубликаты строк убраны (было x2–x3).
- `logger.py` больше не создаёт файлы при импорте — Alembic работает без прав на `logs`.
- CORS берётся из `AMI_ALLOWED_ORIGINS`.
- `MarketStatistics.total_volume` — `Float`, пишется сумма, а не количество.
- Аномалии считаются **только внутри `product_id`**, только недооценённые,
  с `min_sample` (по умолчанию 5).
- `COUNT` в списках — через SQL, лимит `per_page` = 200.
- Добавлены `__init__.py` в `routers/`, `schemas/`, `services/`, `domain/`.
- Удалён пустой каталог `migrations/` (дублировал `backend/alembic`).

## Изменения поведения

| Было | Стало |
|---|---|
| API открыт всегда | при заданном `AMI_API_KEY` нужен `X-API-Key` |
| `./ami.db` относительно CWD | всегда `backend/ami.db` |
| `AMI_DEBUG=true` | `false` по умолчанию |
| Дата из CSV роняла запрос | парсится или пропускается с предупреждением |
| Аномалии по всей категории | по каждой модели отдельно, только недооценённые |
| Тесты в рабочей БД | временная БД в `tests/.ami_tests_*` |
